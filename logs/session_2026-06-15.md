# Session Log — 2026-06-15

## Summary
Started as "why are UAP videos failing with a 400 when Supadata still has credits?" — turned
into a full incident: an expired YouTube Data API key, a stale long-running worker, an Oracle
host OOM + recovery, a credential rotation, and two shipped admin/UI features.

---

## 1. Root cause: expired YouTube Data API key (NOT Supadata)
- The error `YouTube Videos API error 400: "API key expired"` is thrown only in
  `src/lib/youtube/scraper.ts` (`fetchVideoMetadata`), which calls Google's **YouTube Data API**.
  It is the FIRST step of intake, before Supadata (transcripts) is ever called — so Supadata
  credits are irrelevant.
- 320 UAP videos failed identically (first 2026-06-12, every nightly run after). The key in
  `.env.local` had been recreated as `...WI0gE` (Secret Manager v2, commit 455f8e7, June 11),
  but the **pm2 `profound-worker` had 13 days uptime** and `rapid-process.ts` calls
  `dotenv.config()` only at startup → it held the OLD (deleted) key in memory forever.
- NDE was unaffected because its crontab scanners spawn a fresh `tsx` process per tick and
  re-read `.env.local` every run.

### Fix
- `pm2 restart profound-worker --update-env` → reloaded the working key. Verified live: metadata
  scrape succeeds, 0 failures.
- Reset the 320 `API key expired` rows back to `pending` (processed_at=NULL).
- Added `isFatalYouTubeKeyError()` halt guard to `scripts/rapid-process.ts` so a dead key stops
  the whole batch (mirrors the Supadata quota halt) instead of silently burning the queue.

## 2. Oracle deploy gap + deploy script
- Oracle does **not** auto-pull from GitHub. It was a manual checkout on `main`, 59 commits
  behind. Confirmed no cron/systemd/webhook pull mechanism.
- Added `scripts/deploy-oracle.sh` (ff-only pull, npm ci only if deps changed, pm2 restart).

## 3. Oracle host OOM incident (1 GB VM) + permanent fix
- Running `npm ci` (Next.js, ~1334 pkgs) while the worker processed videos exhausted the 1 GB
  RAM → the VM wedged twice (forced reboot via Oracle console to recover).
- **Permanent fix: added a 2 GB swapfile, persisted in `/etc/fstab`.** With swap, npm ci
  completes (slow, ~19 min through swap) without wedging.
- Updated `deploy-oracle.sh` to `pm2 stop` the worker during npm ci for headroom.
- After repair: node_modules whole, worker online, full pipeline verified (YouTube + Supadata).

## 4. Security: rotated the leaked GitHub PAT
- Oracle's git remote embedded a classic `ghp_` PAT in plaintext (`.git/config` + `.bash_history`).
- Switched Oracle to a **read-only SSH deploy key** (`~/.ssh/github-deploy`), remote now
  `git@github.com:...`. Scrubbed token from config + history.
- Identified the exact token by scope (`repo`-only) = "oracle server connection" classic PAT;
  user revoked it (verified HTTP 401 dead). Oracle pulls fine over the new key.

## 5. "Is the queue working?" — yes
- The worker processed 78 UAP today (✅55 / ⏭️23 / ❌0), hit the 80/day cap at 15:53 UTC, then
  slept until midnight UTC by design. The 80/day cap exists for the Supadata ~3,000/mo budget.
- Static `pending` count during the idle window looked like a stall but was the throttle working.

## 6. "Completed videos aren't visible" — verified added; visibility was the issue
- Confirmed via SQL: 57 new `uap_vids` rows today, all `intake_status='complete'`, tier 1/2.
  Real processing, not `already_exists` inflation.
- Why not visible:
  - Scanner "Complete" tab "Age" = `created_at` (when QUEUED), and the worker drains
    oldest-queued first, so completions show old queue dates (~6/8). No "completed date" column.
  - `/uap/video-explore` had `revalidate=86400` (24h ISR) and sorts by YouTube publish date;
    the backlog videos are old-published (2021–May 2026), so they were buried.

## Lessons learned
- A long-running pm2/node process only reads `.env.local` once — rotating env requires a restart,
  not just a file edit. Crontab `tsx` ticks self-heal; pm2 workers don't.
- Never `npm ci` on a 1 GB box without swap. Swap is now permanent.
- "YouTube Videos API error 400" = YouTube Data API key, never Supadata.
- The scanner "Age" column means queue-date, not completion-date — a known UX confusion.
