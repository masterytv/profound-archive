## Key Architectural Decisions

### 1. Questions Page: DB as Single Source of Truth
- **Problem:** `/questions` page had hardcoded question arrays that were completely different from `nde_questions` table content (researcher-style questions).
- **Fix:** Reseeded `nde_questions` with 81 consumer-facing questions from `nde_questions_hyde.md`. Page is now an async Server Component that fetches from the DB.
- **Slug source:** Slugs come directly from `nde_questions.slug` — no `toSlug()` conversion needed.

### 2. Timestamp Fix: Wrong RPC
- **Problem:** `/api/questions/[slug]` was calling `nde_chatbot_match` which queries `nde_chatbot_chunks` — a table that intentionally has no `start_time`.
- **Fix:** Switched to `nde_questions_match` which queries `nde_punctuated_embeddings` — correct table with `start_time` column.
- **RPC change:** Added `date` to the `nde_questions_match` return table (required DROP + recreate — Postgres doesn't allow return type changes via ALTER).

### 3. CASCADE Truncate Required
- `nde_questions` has a foreign key from `question_answers`.
- Truncating without CASCADE fails. Always use:
  `TRUNCATE TABLE public.question_answers, public.nde_questions RESTART IDENTITY CASCADE;`

- Replaced centered part dividers with left-justified category headers using coloured left-border accent.
- All interactive elements have `cursor-pointer` and `transition-all duration-200` per UX skill.

## Lessons Learned
- See `docs/LEARNINGS.md` Section 17 for the persistent record.
- Always check which table an RPC queries (`nde_chatbot_chunks` vs `nde_punctuated_embeddings`) — they serve different purposes and have different columns.
- Changing a Postgres function's return type is not allowed via ALTER — always DROP and recreate.
