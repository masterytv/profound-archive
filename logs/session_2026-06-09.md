## Issue: /channels page timing out (~20s response)

### Context
Tom upgraded the Supabase DB just before the issue occurred. Disk I/O budget was low due to concurrent video processing pipeline (AI scan runs). Both factors likely contributed — low I/O made the slow query catastrophic.

### Root Cause (combined)
1. **Low disk I/O budget** — DB upgrade + active video processing pipeline exhausted the buffer pool (1,372 disk reads in EXPLAIN vs 297k buffer hits = lots of cache eviction under pressure)
2. **`get_channel_stats()` query design** — 9 correlated subqueries × 53 channels = 477 sequential sub-selects, inherently slow even on full compute

### Fix Applied
Created `nde_channel_stats_mv` materialized view — same pattern as `uap_channel_stats_mv`.
- Migration: `20260609_nde_channel_stats_materialized_view.sql`
- Rewrote `get_channel_stats()` RPC to `SELECT * FROM nde_channel_stats_mv`
- Added `pg_cron` refresh daily at 6:30 UTC

| /channels page | ~20s | 0.8s |
