# Session Log — 2026-06-22

## Mission: Admin Operations & Cost Control (cost visibility + pause switches)

Goal: one admin page to (1) see every paid process, the APIs each uses, their
keys, live quota usage and cost; and (2) pause cost-incurring work selectively
(e.g. stop video ingestion when out of money) while chat/search stay online.

### What already existed (built on, not reinvented)
- `api_usage_log` table + `src/lib/ai/usage-tracker.ts` (token logging via
  `trackedChat`/`wrapAiClient`) + `pricing.ts` (token price table).
- `src/lib/ai/budget.ts` — auto dollar-cap guard ($20/day, $50/mo), fails open.
- `/admin/usage` dashboard — token spend by operation/provider/model.

### Gaps closed
1. Tracking only covered token AI (OpenAI/OpenRouter). YouTube quota & Supadata
   credits — the costliest, user-named services — weren't tracked at all.
2. No manual pause — only the automatic dollar cap.

### Architecture decisions
- **Pause state lives in Postgres** (`service_switches`), not env/memory, so it's
  honored by every trigger path: Oracle crontab, pg_cron, and manual admin runs.
- **Gate at the route handlers** (the actual automation entry points), not deep
  in pipeline libs — uniform, low-risk. Paused = HTTP 200 `{skipped:true}` (not
  an error) so cron callers don't retry-storm.
- **`isPaused()` fail-OPEN** with a 5s TTL cache + last-known-good fallback
  (mirrors budget.ts philosophy — the switch must never wedge all pipelines).
- **Master switch = paid work only.** Never gates chat/search/page-serving.
- **Quota counters are real**, instrumented at the call sites via `logQuota()`.
